# Data dictionary

## Evidence classes

- **PUBLIC_OBSERVATION:** a field transcribed from a public source, with its
  original definition and provenance retained.
- **DERIVED:** a deterministic transformation of source values (for example,
  deduplication or multiplying by a scenario parameter).
- **ASSUMPTION / SCENARIO:** an input chosen for sensitivity analysis rather
  than measured or verified from an operating organization.
- **HYPOTHETICAL_SCENARIO:** a model output under scenario assumptions. It is
  not a confirmed donation or delivery.

## Public restaurant source records

`data/raw/south_korea_large_food_waste_generators.csv` preserves the downloaded
source extract. `data/processed/korea_restaurant_waste_observations.csv` and
`data/processed/korea_seoul_restaurant_waste_observations.csv` are processed
restaurant-classified tables with original identifiers and source references.

| Field | Meaning |
|---|---|
| `observation_id` | Snapshot-local source-row identifier, not a government-issued establishment ID. |
| `business_name`, `business_type` | Public-source name and classification. |
| `administrative_locality`, `road_address`, `lot_address` | Public-source location fields; some may be incomplete. |
| `declaration_date`, `source_reference_date` | Source date fields; neither establishes the waste-measurement period. |
| `raw_reported_discharge_quantity` | Source `PROD_QTY`; expected food-waste discharge in kg/month. Not observed edible or donatable food. |
| `quantity_unit_status`, `quantity_period_status` | Field-standard unit/meaning metadata. |
| `model_supply_eligibility` | `NOT_ESTABLISHED` in the public extract. |
| `source_id`, `source_url`, `snapshot_date` | Provenance fields. |

## Refined Seoul scenario tables

### `data/scenario_refined/sender_observations.csv`

One row per deduplicated Seoul sender. The separate field
`reported_expected_waste_kg_month` is the source observation; it must not be
renamed or described as measured edible surplus.

| Field | Meaning |
|---|---|
| `sender_id` | Original source observation ID retained by the scenario deduplication rule. |
| `business_name_original_ko`, `address_original_ko`, `administrative_locality_original_ko` | Original Korean source fields. |
| `reported_expected_waste_kg_month` | Source quantity \(W_i\), expected waste kg/month. |
| `quantity_definition` | Explicit source definition and non-edibility caveat. |
| `source_reference_date`, `source_id`, `source_url`, `snapshot_date` | Source provenance. |

### `data/scenario_refined/supply_fraction_scenarios.csv`

Separate derived scenario values; the source observation remains in its own
column.

| Field | Meaning |
|---|---|
| `reported_expected_waste_kg_month` | Source \(W_i\), not eligible food. |
| `eligible_fraction_alpha` | Illustrative scenario parameter; tested values are 0.05, 0.10, 0.20, 0.30, and 0.40. |
| `scenario_supply_s_i_kg_month` | Derived value \(s_i=W_i\alpha\); not measured edible surplus. |
| `evidence_type`, `assumption_note`, `source_id` | Scenario classification and traceability. |

### `data/scenario_refined/google_restaurant_closing_times.csv`

Partial, manually checked Google Search/Maps hours enrichment. It is separate
from the government waste observations and currently covers only a small
location-matched subset of the 1,795 Seoul sender records. Missing sender/day
rows mean unknown, not closed or open.

| Field | Meaning |
|---|---|
| `sender_id` | Corresponding sender record in `sender_observations.csv`. |
| `day_of_week` | Local operating weekday for the closing-time observation. |
| `closing_time_local` | Google-displayed local closing time in `HH:MM`; blank or absent records are unknown. |
| `source_platform`, `google_search_query`, `checked_date` | Lookup provenance and check date; search results may change. |
| `match_status` | `matched_name_address` for a location-matched result. `same_location_alias` marks a likely duplicate/alias at the same premises and is retained for audit but excluded from deadline evaluation. |
| `notes` | Match qualification, conflicting evidence, or day coverage. |

For included records, the scenario window is the restaurant's own closing
time through two hours later. Direct pair feasibility uses OSRM road distance
divided by an assumed average speed, not a Google Maps ETA. Multiple pickups
and cumulative route time are not modeled.

### `data/scenario_refined/seoul_restaurant_hours_coverage.csv`

One row per sender, generated by
`scripts/build_seoul_hours_coverage.py` from the Seoul Open Data tourist-food
dataset. It is an exhaustive coverage ledger, **not** a complete hours dataset:
unmatched restaurants remain explicitly unknown.

| Field | Meaning |
|---|---|
| `source_match_status` | Exact normalized Korean business name and road-number match, ambiguous duplicate source records, or no exact match. |
| `operating_hours_raw` | Source schedule text, not normalized into day-specific closing times. |
| `source_candidate_hours_raw` | Conflicting source schedule strings retained for review; do not use as a verified schedule. |
| `source_record_ids`, `source_business_name_ko`, `source_road_address`, `source_record_url` | Matched record provenance. |
| `source_dataset_id`, `source_dataset_updated`, `source_license` | Dataset identifier, portal update date, and license attribution. |

The source schedule may omit weekdays, include break/last-order details, or
contain text that needs review. It does not by itself establish the specific
closing time for every weekday or the user's collection window.

## Receiver-capacity scenarios

`data/scenario/receivers.csv` is the preserved v1 directory-derived scenario.
Its `effective_receiving_capacity_kg` values are not measured capacities.
`data/scenario_refined/receiver_capacity_shares.csv` stores \(q_j\) shares used
by the new scenario engine.

| Field | Meaning |
|---|---|
| `capacity_distribution` | Named deterministic share scenario: uniform, linear rank, quadratic rank, or 75%-concentrated. |
| `receiver_id` | Public-directory site identifier. |
| `receiver_capacity_share_qj` | Scenario share \(q_j\), nonnegative and normalized to sum to 1 within each distribution. |
| `evidence_type`, `assumption_note` | Explicitly identify hypothetical rather than observed capacity shares. |

For each experiment, actual scenario capacity is
\(C_j=\beta(\sum_i s_i)q_j\), where tested \(\beta\) values are 0.50, 1.00,
and 1.50. The Korea Foodbank directory does not publish additional site
capacity in kilograms.

## Geographic eligibility and route data

`data/scenario/eligibility_matrix.csv` is preserved as the complete v1 route
matrix. In v2, the `eligible` decision is generated for each experiment from
the route distance threshold and optional strict coordinate-quality filter.
It is **geographic_eligibility**, not verified operational eligibility.

| Field | Meaning |
|---|---|
| `sender_id`, `receiver_id` | Pair endpoints. |
| `road_distance_km` | OSRM driving-profile point-to-point route-distance estimate. |
| `eligible` | In v1, the requested all-pairs scenario assumption. In refined experiments, a hypothetical geographic-distance/quality filter. |
| `eligibility_evidence`, `source_id` | States the rule and scenario provenance; does not establish donation acceptance. |
| `road_distance_source`, `road_distance_retrieved_at_utc` | Route provenance and retrieval timestamp. |

`data/processed/seoul_osm_geocoding.csv` stores unique address-query evidence.
`data/processed/seoul_osm_routed_locations.csv` stores node-level coordinates,
match quality, OSRM snap points and offsets, and source metadata. See
`docs/route_quality_audit.md` for quality counts, repeated coordinates, zero
distances, and the strict scenario rule.

## Experiment output

`data/scenario_refined/scenario_experiment_results.csv` contains one row per
parameter combination and greedy order. Important fields:

- `scenario_id`, `parameters_json`, `random_seed`: deterministic experiment
  identity/configuration. Current methods use no random draws; the seed is
  recorded as zero for explicit reproducibility.
- `eligible_fraction_alpha`, `total_capacity_ratio_beta`,
  `capacity_distribution`, `maximum_road_distance_km`,
  `strict_geographic_quality`, `sender_processing_order`: scenario settings.
- `lp_stage1_optimal_kg`, `lp_stage2_allocated_kg`,
  `lp_stage2_total_kg_km`, `lp_average_km_per_allocated_kg`: lexicographic LP
  outputs.
- `greedy_allocated_kg`, `greedy_total_kg_km`,
  `greedy_average_km_per_allocated_kg`: nearest-receiver baseline outputs for
  the named fixed sender order.
- `lp_minus_greedy_kg`, method-specific unallocated supply, and remaining
  receiver capacity: direct comparison metrics.
- `result_evidence_type`: always `HYPOTHETICAL_SCENARIO` for this study.

## Legacy generic upload schema

The existing upload interface remains available for user-provided data. Its
legacy column `eligible_surplus_kg` means eligible supply declared by that
uploader and requires source evidence. It is not the Seoul source variable
`reported_expected_waste_kg_month`. Legacy files under `data/scenario/` are
preserved for v1 reproducibility; do not interpret their all-waste scenario
field as observed edible surplus.
