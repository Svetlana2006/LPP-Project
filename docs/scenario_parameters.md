# Seoul refinement scenario parameters

The experiment engine varies source interpretation, assumed capacity, the
geographic network, coordinate quality, and greedy processing order. Every
output is a hypothetical scenario result.

## Supply parameter

For each retained sender:

\[
s_i=W_i\alpha
\]

- \(W_i\): `reported_expected_waste_kg_month`, the public expected waste
  quantity, kg/month.
- \(\alpha\): `eligible_fraction_alpha`, tested at 0.05, 0.10, 0.20, 0.30,
  and 0.40.
- \(s_i\): derived scenario supply, not observed edible/unserved food.

These alpha values are sensitivity settings, not measured or statistically
estimated redistribution fractions.

## Receiver-capacity parameters

\[
C_j=\beta\left(\sum_i s_i\right)q_j,\qquad
q_j\ge0,\qquad \sum_jq_j=1.
\]

Tested `total_capacity_ratio_beta` values are 0.50, 1.00, and 1.50. Capacity
shares are deterministic, normalized scenario allocations:

1. `uniform`: equal share for each of the 32 directory sites.
2. `linear_rank`: shares proportional to receiver-ID alphabetical rank.
3. `quadratic_rank`: shares proportional to the square of that rank.
4. `concentrated_75_percent_first`: 75% to the first alphabetical receiver ID,
   with the other 25% split evenly among the rest.

These are deliberately varied shapes for sensitivity testing; none represents
known food-bank capacity or demand.

## Geographic network scenarios

`geographic_eligibility` is true in a scenario if the OSRM driving distance is
within \(\tau\), for \(\tau=5,10,15,20,25\) km. A complete-network benchmark
also remains available. These are hypothetical distance filters, not verified
NGO service radii or permission to donate.

The strict-quality variant further requires both endpoint geocodes to have a
road-and-house-number Photon match and OSRM snap metadata. It excludes
uncertain location records from edges. It does not remove distinct businesses
solely because their coordinates are the same.

## Greedy processing orders

All orders use nearest remaining eligible receiver first, with receiver ID as a
tie-break:

- `sender_id`
- `fewest_eligible`
- `largest_supply`

`reverse_sender_id` remains available for deterministic interactive
experimentation. The main 2,160-row grid does not use a deadline order because
the public source has no restaurant deadlines. A separate hypothetical pickup
window experiment is documented below.

## Restaurant-specific pickup-window experiment

The public Seoul records do not include actual business closing times or route
durations. The separate `run_seoul_deadline_experiment.py` therefore uses
explicitly hypothetical per-restaurant closing times (20:00, 21:00, 22:00, or
23:00), with balanced assignments varied across deterministic seeds. Each
restaurant has its own deadline:

\[
d_i=\text{close}_i+2\text{ hours}.
\]

NGO collection start is tested at 20:00, 21:00, and 22:00. Estimated direct
drive time is the existing OSRM road distance divided by scenario speeds of
15, 20, or 25 km/h. A pair is retained only when direct estimated arrival from
that NGO's site is no later than that restaurant's individual deadline. No
Google Maps API, paid API, or additional external request is used.

The deadline experiment uses the original all-reported-waste supply
(\(\alpha=1\)), uniform equal receiver capacities totaling supply
(\(\beta=1\)), and complete source route matrix before deadline filtering.
Both LP and greedy receive the same filtered edges. This pairwise rule keeps
the LP continuous and simple, but it does not model an NGO's cumulative
restaurant-to-restaurant route, stop order, loading time, or traffic. It is
not the full route-order constraint in the user's motivating example.

The legacy result tables and assumed schedules were removed during repository
cleanup. The numerical summaries in the historical experiment report below
remain for context, but those deleted CSVs are no longer available for
reproduction. Current source-hours results are generated separately by
`scripts/run_seoul_deadline_experiment.py`.

## Reproducibility and scale invariance

The legacy deadline-window results and assumed schedules were removed during
repository cleanup. Current source-hours experiments are reproducibly
generated by `scripts/run_seoul_deadline_experiment.py`.

All \(\alpha\) values scale every sender supply and every \(\beta\)-based
receiver capacity by the same factor. Therefore, for a fixed \(\beta\),
capacity-share shape, geographic network, and quality setting, the feasible
polytope scales uniformly. The experiment runner solves once at \(\alpha=1\)
and scales allocation and kg-km metrics linearly for the requested alpha
values. The app still solves the selected scenario directly.

## Experiment grid

The saved grid crosses:

- 5 alpha values
- 3 beta values
- 4 capacity-share scenarios
- 6 geographic networks (five thresholds plus complete network)
- 2 coordinate-quality modes
- 3 greedy orders

This yields 2,160 comparison rows. The LP rows are identical across greedy
orders for a fixed parameter configuration; the repeated rows make each
LP/greedy comparison self-contained. No deadline-first rows are generated in
this main grid.
